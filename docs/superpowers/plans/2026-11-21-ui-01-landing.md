# UI-01 Landing Page Implementation Plan

> Use superpowers:executing-plans and the eight frontend skills for this bounded checkpoint.

**Goal** — Deliver the approved editorial guest homepage with truthful navigation and real photography.

**Architecture** — Render a dedicated landing component from the existing public route fallback. The homepage reads the Express catalog and the same published review response as the existing review route. Landing styles and media remain scoped to UI-01.

**Tech stack** — React, TypeScript, CSS, Tailwind and Vite, with the existing Express endpoints.

**Spec** — [UI-01 landing design](../specs/2026-11-21-ui-01-landing-design.md).

## Global constraints

Use the current checkout on main, which contains the supplied photo originals. Preserve online booking, guest and staff authentication, backend rules and default feature gates. Use local fixtures and leave hosted Supabase untouched. Keep payment media outside the frontend and exclude the attendee image from published assets. Keep UI-02 pending visual approval.

## Review focus

- Closed feature routes still resolve to the homepage where the existing router expects it, while active staff routes and onboarding keep their existing behavior.
- Catalog and reviews may be delayed, empty or unavailable. Navigation remains usable and the homepage omits unavailable prices and reviews.
- Long review text and a broken gallery image must fit at 320 px and at the wide desktop breakpoint.
- A keyboard-triggered or rapidly reversed mobile disclosure updates focus and accessible state immediately.
- The original QR and attendee photo stay out of the production artifact and the local development server rejects direct access.
